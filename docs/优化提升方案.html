德州扑克练习台
代码与体验审计

这是一个底子比多数个人项目好得多的东西：分层干净、265 个用例、10 道验收闸门、依赖只有 React。 但它真正要卖的那件事——「打完知道自己错在哪」——目前是断的。 复盘的「建议动作」几乎恒为加注，分级被底池大小支配； 同时结算态、手机竖屏、九人桌三处界面存在硬缺陷。 下面这份东西先给证据，再给按优先级排列的修法。

00结论

先说判断，再说理由。四条，按该动手的顺序排：

  • P0 · 语义

    复盘的建议动作退化。实测两手共 10 个决策点，10 次「建议动作」全是加注；一手 5 个决策点里 4 个被判「明显偏离」。这不是阈值调紧，是 EV 模型本身给任何下注附赠了一份凭空的弃牌收益。

  • P0 · 崩溃

    开发模式下「下一手」必现白屏。打完一手（走到河牌）再开下一手，整页清空，控制台一条 [showcase] 揭示的张数 5 超过真实公共牌 0。生产构建因为断言被摇掉而不复现，所以 35 个 E2E 结构性看不到它。

  • P0 · 布局

    座位是绝对定位的固定尺寸卡片，牌桌却是流式缩放的。这一条同时解释了三处坏相：结算态座位压住公共牌、手机竖屏座位互相重叠且自己的底牌看不见、九人桌有一个 AI 被另一个精确盖住。

  • P1 · 节奏

    一手 20–30 秒，且不可跳过。练习工具的核心指标是单位时间的决策次数，现在为了「拟真」把它砍了一半，却没有留加速开关。这是最便宜、回报最高的体验改动。

一句话总结：该修的是反馈回路，不是像素。换皮不会让这个工具变好，让「建议动作」重新可信才会。

02P0
三个硬伤
P0-1

复盘的「建议动作」恒为加注，分级被底池大小支配

现象

实测两手（6 人桌、中等 AI、全程只按「跟注 / 过牌」打），复盘表共 10 个决策点：「建议动作」列 10 次全是加注，其中 8 次被判为偏离（5 次「明显偏离」、3 次「值得复盘」）。EV 损失从 4.63 到 611.54 不等——而表下写着阈值是「> 0.5BB 值得复盘，> 2BB 明显偏离」。

根因

estimateEvs 的加注分支：

const sizeRatio = invest / Math.max(bigBlind, pot);
const calledProb = Math.max(0.25, Math.min(0.75, 0.75 - 0.12 * sizeRatio));
const evWhenCalled = equity * potAfter - (1 - equity) * invest;
const evWhenFold = pot;
const raise = calledProb * evWhenCalled + (1 - calledProb) * evWhenFold;

三件事叠在一起：

  • 被跟注概率与牌力无关。calledProb 只由下注尺度决定，下限硬编码 0.25、上限 0.75。于是任何下注都白得 25% 的弃牌收益，与你手里是坚果还是空气无关。
  • 被跟注时的胜率仍等于摊牌胜率。现实里跟注你的范围会显著强于随机手牌，模型没有这个衰减。
  • 基线不统一。弃牌分支固定为 0（「当前时点基准」），加注的未跟注分支却直接给 pot——而底池里本来就含着你自己的投入。两条分支量的不是同一个东西，相减得出的「EV 损失」因此失去了经济含义。
量化：这套公式会怎么判

把公式单独拎出来，扫描「无人下注、你加注半个底池」这一最常见场景：

胜率过牌 EV加注 EV建议EV 损失（BB）分级
5%2013.6过牌0.00正常
10%4041.2加注0.12正常
15%6068.8加注0.88值得复盘
25%100124.0加注2.40明显偏离
40%160206.8加注4.68明显偏离
80%320427.6加注10.76明显偏离

底池 400、大盲 10 时：只要你还有 10% 以上的胜率，模型就说「加注」，而过牌会被判成「明显偏离 2.4–13BB」。分级于是变成了底池大小的函数，而不是决策质量的函数——一手牌越打越大，后半段的每个决策都注定「错」。

这对一个新手的杀伤是具体的：翻牌用垃圾牌过牌是正确的，工具告诉他「明显偏离，应该加注」。他要么学会乱开火，要么不再相信这个工具。

修法

不用引 GTO（那是产品定位之外的事），但要把这条公式从「无条件奖励进攻」改成「奖励有依据的进攻」：

  • 让弃牌概率吃牌力。例如 p_fold = clamp(0.55 − 0.5·equity − 0.35·sizeRatio, 0.05, 0.60)。空气牌诈唬才有弃牌收益，强牌靠摊牌价值。
  • 让被跟注时的胜率衰减。e_called = equity · (1 − 0.3·sizeRatio)：下注越重，跟注范围越强。
  • 统一基线。所有分支一律以「弃牌 = 0」为原点，未跟注分支的收益是 pot − 你本可以过牌拿到的期望，而不是裸 pot。
  • 把「最优动作」改成「可接受集合」。EV 在最优值 0.2BB 以内的动作都算正常，只对真正的数量级偏离标黄。单点最优会把「跟注 vs 加注差 5 筹码」渲染成道德错误。
  • 单位统一。面板与 CSV 一律输出 BB，表头写 EV 损失 (BB)，筹码值放 title 里。
预期效果

非「正常」决策占比从当前的约 80% 回落到 20–30%（这个数可以直接测：固定种子跑 200 手，统计 grade 分布）；「建议动作」列重新出现弃牌与过牌；大底池不再自动等于「明显偏离」。

验收

新增单测三条：① 同一胜率下，下注尺度越大 p_fold 越低；② 胜率 5% 面对下注必须建议弃牌（当前会建议加注）；③ 200 手固定种子的 grade 分布快照。第三条是关键——现在 tests/unit/review.test.ts 只断言了跟注分支与单调性，加注分支没有任何基线断言，所以这个缺陷能一路绿灯到现在。

P0-2

开发模式下点「下一手」必现白屏

现象

打完一手（公共牌发到河牌 5 张），点「下一手」——页面清空，只剩背景色。document.body.innerText.length === 0，连顶栏都没了。两次独立复现。

PAGEERROR: Error: [showcase] 揭示的张数 5 超过真实公共牌 0
    at src/ui/useTableShowcase.ts:299
根因

useTableShowcase 用两个 effect 处理同一个跨手状态：一个在 handId 变化时把「已揭示张数」游标重置为 0，另一个在每次提交时检查「游标不得超过真实张数」。同一 commit 里，检查 effect 读到的是新牌局（0 张公共牌）配旧游标（5 张），而重置是通过 setState 排队的，要下一轮渲染才生效。于是断言先于重置触发。

更严重的是断言的写法：它直接 throw。项目里没有任何 ErrorBoundary，一次 effect 抛错就让整棵树卸载——这就是全屏空白而不是「某个区域降级」的原因。

为什么 265 个用例没拦住

因为 playwright.config.ts 的 webServer 跑的是 npm run preview，即生产构建；而这类断言被 process.env.NODE_ENV === 'production' 整块摇掉。我在 dist/assets/index-*.js 里 grep 那句错误文本，命中数 0——生产包里它根本不存在。所以 CI 全绿，开发者本地每次都会撞上。

这类缺陷值得单独立一条规矩：如果一条不变量只在开发期生效，那它也必须有一条在开发期跑的自动化用例；否则它的唯一作用就是随机惩罚开发者。
修法
  • 把游标改成派生量而不是同步状态：revealed = min(cursor, board.length)，并让 cursor 带上 handId 前缀（{handId, n}），换手时旧值天然失效——不需要 effect 去重置。
  • 断言改为 console.error + 自愈（clamp 到合法值），不再 throw。
  • 加一个最小 ErrorBoundary：捕获后显示「重新发牌 / 导出存档 / 清空存档」三个出口，而不是白屏。
验收

dev server 下连打 20 手不白屏；verify 里增加一步「dev 模式冒烟」（起 vite 而非 vite preview，跑 2 手并断言无 pageerror）。

P0-3

座位是绝对定位，牌桌是流式缩放：三处布局互撞

同一根因，三种症状

TableView.computePlacements 用百分比坐标把座位钉在牌桌上，座位卡本身却是固定尺寸（约 130×150），牌桌高度则随视口与状态在 280–700px 之间伸缩。容器缩、卡片不缩，碰撞是必然的。

① 结算态：座位压住公共牌。结算面板出现时 .felt 的 min-height 被压到 280px，玩家座位仍在 top:90%，卡片向上溢出，正好盖住公共牌第一张；顶排座位则压住底池胶囊。

② 手机竖屏：座位互相重叠，自己的底牌消失。390×844 实测：一个座位的左边界在 x = −6（出了屏幕），顶排两个座位间距 89px 而卡片宽 97px（重叠 8px），玩家座位高度从桌面端的 73px 被压到 51px——两张底牌仍在 DOM 里（querySelectorAll('.card').length === 2），但被容器裁掉，视觉上完全看不见。

③ 九人桌：一个 AI 被另一个精确盖住。computePlacements 在 n=9 时产出 9 个位置，但其中两个的 getBoundingClientRect() 完全相同（left 1062, top 124）。画面上只能数到 7 名 AI + 自己，有一名对手的筹码、底牌、动作全部不可见。

修法（不建议再打补丁）

停止在「绝对定位 + 百分比」上加 clamp()。改成两层结构：

  • 座位挂在桌沿外侧，用一条椭圆轨道定位（按角度分布，而不是手写坐标表）：牌桌缩小，座位跟着沿轨道靠近，永不进入桌面中心区。
  • 座位卡改为「紧凑/标准」两档密度，由容器宽度决定（@container 或 ResizeObserver），窄屏只留名字 + 筹码 + 动作，底牌以小尺寸常驻。
  • 玩家座位永远在牌桌之外，固定在操作条上方，不参与桌面布局。
  • 气泡锚在一侧（顶排向下、左侧向右、玩家向上并且避让底池区），而不是统一定在座位正上方。
验收

加一条几何断言（现在完全没有）：在 390×844 / 1024×768 / 1440×900 三个视口、2/6/9 三种人数下，断言所有 .seat 两两不相交、都在视口内、玩家座位的两张牌可见，且 .board 与任何 .seat 不相交。这类断言比截图对比稳定得多，成本也低。

03P1
体验与教学闭环
P1-1

练习节奏 20–30 秒一手，且不可跳过

AI 每步思考 1100–2400ms，6 人桌一手 12–20 个 AI 决策，单手墙钟 20–30 秒。README 自己记录了这次退化（从 8–14 秒）。对「练习」这个定位，时间就是吞吐量：30 秒一手意味着 10 分钟只能打 20 手，样本量根本不够形成统计意义。

修法

节奏做成三档放进设置：拟真（现状 1.1–2.4s）/ 快速（0.35–0.6s，设为默认）/ 瞬时（0，直接呈现终局，适合复盘时回看）。再加一个「长按 S 跳过当前等待」——它只压缩等待，不改变任何决策。

预期

默认档下一手 8–12 秒，练习吞吐约为现在的 2.5 倍；想体验节奏的人仍可切回拟真。

P1-2

「提示」在当前设计里几乎用不到

点击「查看提示」后，提示框作为整行块插入横向仪表盘下方，仪表盘整体变高，「建议」那一行被推到视口之外。也就是说：你点了提示，最想看的那句结论看不见，还得滚动。实测响应 194ms，速度没问题，位置有问题。

修法

把提示从「下方插入的块」改成「桌面上的就地叠加」：在底池胶囊正下方画两条对齐的横条——你的胜率 vs 底池赔率要求，谁长谁短一眼可判；建议动作以一行文字浮在操作条上方，不改变任何布局高度。真正该保留的约束是「查看次数计入统计」，位置不必绑在操作条里。

P1-3

复盘表：单位、版式、窄屏

三个具体问题：① EV 损失列是筹码，阈值文案是 BB，两者并列且都没标单位，玩家无法把 611.54 和「2BB」对上；② 牌面被推到 700px 之外——「你的底牌」标签在左端、牌在右端，中间一片空白（这是 .settings-row 用 space-between 撑满整行的结果）；③ 10 列表格在 1100px 以下必然溢出，手机端不可读。

修法

单位统一为 BB 并在表头标注；把「底牌 / 公共牌 / 最优五张」从 settings-row 里挪出来，做成一左一右对齐的卡片组，不要横跨整行；表格在窄屏改为逐决策卡片（街 + 你的动作 → 建议动作，下面三个数字，右侧分级标记），一行一条，纵向堆叠。

P1-4

打过的牌不能回看，也不能重放

历史面板只列出动作流水（谁在第几街做了什么），没有回放，也不能从某一手跳进那一手的复盘。而 HandRecord 里已经有 seed、完整 actions、results——回放是纯前端、零新增数据的能力，只是没接。

这是「练习」和「刷手数」的分水岭：能回放，一手牌才可以被反复研究；不能回放，它只是一行统计。建议给每手一个「回放」按钮，复用现有 TableView，用动作序列驱动（不必重新洗牌）。

P1-5

设置改了，界面不说什么时候生效

把桌人数从 6 改成 9，当前这一手仍然是 6 人（实测），界面上没有任何提示。用户第一反应是「设置坏了」。同类问题：盲注、起始筹码、AI 难度都只在下一手生效。修法很轻——设置项下加一行「下一手生效」，或提供一个「立即重开一手」的按钮。

P1-6

误点保护：弃牌与全下都是一击生效

「全下（All-in）」和「弃牌（Fold）」都在单击后立即执行，没有确认、没有撤销。对一个用来练手的工具，一次手滑弃掉大池会直接污染这一手的复盘数据（实际动作被记成弃牌，EV 损失看起来像你真的犯了错）。建议：全下加一步确认（或二次点击），并允许在 AI 行动前撤销上一动作。

无错误边界 全站没有 ErrorBoundary，任何渲染/effect 抛错 = 白屏。 加一层壳，提供「重新发牌 / 导出存档 / 清空存档」。
无障碍缺口 加注滑杆无 aria-valuetext（屏幕阅读器只报数字，不报「加注到 240」）；底池变化与「轮到你」无 aria-live；tab 栏有 role=tab 但缺 aria-controls/tabpanel。 三处都是小改动，收益对键盘/读屏用户很大。四色牌与 reduced-motion 已经做得比多数项目好，补完这三处就完整了。

闸门盲区：两个 P0 恰好都落在缝里

这是这份审计里我最想说的一条。npm run verify 的十道闸门测的都是结构不变量——筹码守恒、牌型直方图、枚举次数、AI 档位可分辨。它们非常扎实，但它们测不出「建议动作是否合理」和「元素是否重叠」。而 E2E 又统一跑生产构建，测不到开发期断言。

结果是：265 个用例全绿，两个 P0 同时存在。建议补三道闸门：

05界面
设计方向

现有视觉是「赌场皮肤」：绿绒椭圆 + 金色描边 + 深色圆角面板。它不算难看，但它把注意力放在了错误的地方——桌面上每个元素的视觉重量几乎相等，每一块都是「圆角面板 + 1px 边框 + 12px 灰字」，彼此争抢，而真正决定这一手输赢的三样东西（我的牌、公共牌、要跟多少）分别是小卡、小卡、一行文字。

我的主张是把这个工具从「赌场」重新定位成「教练的工作台」：牌桌不是布景，是一块显示当前局面的画布；复盘不是第五个标签页，是牌桌旁一直在的一列。

三条原则，其余都是细节：

  • 座位在桌外。桌沿是边界，不是装饰。座位挂在轨道上，牌桌缩它就跟着靠近，永远不会互相压。
  • 金色只给「要你决定的事」。现在金色同时出现在按钮、数字、标签、描边、底池上，主色过载，等于没有主色。收窄到两处：当前该你行动的操作按钮、底池金额。对手与环境信息改用冷色（青灰），人和钱在视觉上分开。
  • 数字一律带单位和对照。筹码旁边给 BB，胜率旁边给底池赔率要求。这个工具的读者是来学「够不够跟」的，任何孤立的数字都是浪费。

字体只需要动一处：把「数字」升成一级信息。所有筹码、底池、胜率、EV 用等宽 + tabular-nums，并统一到 15/24/34 三级；中文正文保持系统黑体（换衬线在 11px 的标签上会糊）。标题的负字距（-3px）对中文是反效果——中文没有西文那种可压缩的字间距，建议改成 -0.5px 并加 0.01em 的行内间距。

开始界面：给回访者一条更快的路

现在它是一张落地页。对回访者，真正想知道的是「上次打到哪、今天还剩多少 BB、直接继续」。建议把主按钮改成「继续（第 47 手 · 128BB）」，参数卡收进一个「调整本局」的折叠区，装饰牌换成一张「最近 10 手的盈亏走势」小图——它是这个工具唯一能给的、有信息量的首页内容。

06路线图

按依赖排序，不按「好不好做」排序。前两步不做完，后面的体验改动都是在坏地基上刷漆。

迭代 1

让反馈重新可信　P0-1 + P0-2

改 EV 模型的弃牌概率与胜率衰减、统一基线、EV 损失改用 BB；游标改派生、断言改自愈、加 ErrorBoundary。

验收：200 手固定种子的 grade 分布落在目标区间 20–30%；dev 连打 20 手无 pageerror。
迭代 2

重做座位布局　P0-3

椭圆轨道 + 两档座位密度 + 玩家固定在桌外 + 气泡避让。同时清掉结算态的重叠与重复按钮。

验收：3 视口 × 3 人数，座位两两不相交、底牌可见、无横向滚动（G12）。
迭代 3

补教学闭环　P1-1 / P1-2 / P1-4

三档节奏 + 跳过等待；提示改为桌面就地叠加；历史加「回放」。

验收：默认档一手 ≤12s；提示展开不改变操作条高度；任意历史手牌可回放。
迭代 4

还技术债　P2 + P1-3 / P1-5 / P1-6

状态不可变化、删死代码、拆 hook 与 CSS、补 G11–G13、加误点保护与设置生效提示。

验收：verify 13 道闸门全绿；viewKey 这类字符串依赖键消失。

不建议做的

  • 不要先换皮。视觉重做会让上面所有几何问题重新长一遍（座位重叠本质是布局系统的缺陷，不是配色问题）。先修布局系统，再谈配色。
  • 不要做 GTO。README 已经明确不做，这是对的：求解器会把项目从「练习工具」变成「研究工具」，成本与定位都不匹配。让启发式模型变得诚实（知道自己不知道）比让它变精确更划算。
  • 不要在现有绝对定位上继续加 clamp()。那个方向已经产出三个 bug 了。
  • 不要加多人联机。单人 + 可回放 + 统计，这条线还没做透。
