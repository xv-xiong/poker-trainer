## 阶段 2-1：首屏直接编辑建桌参数（用户新增需求，已完成）

> ✅ **状态：已完成**。用户要求：在首屏就能改桌人数 / 起始筹码 / 盲注 / AI 难度，
> 不必进入游戏后才能改。编号 2-1（介于阶段二与阶段三之间），阶段三（手牌回放）暂缓。

**为什么这条需求本身是对的**：这些参数只在上桌前有意义，而此前首屏是**只读**展示，
想改得先进牌桌 → 翻设置页 → 改完那里还标着「下一手生效」，绕两屏才生效，
很容易被当成「改了没反应」。

**做了什么**

1. `src/ui/components/StartScreen.tsx` 重写：`.lobby-facts`（4 个只读 dt/dd）换成
   `[data-testid="lobby-setup"]` 表单（桌人数 / AI 难度 / 起始筹码 / 盲注小大），
   加「继承上一手筹码」开关（它决定起始筹码的含义，属上桌前必须定下的模式）。
2. **单一真相源**：删掉 `StartScreen` 自己读 `localStorage` 的 `readSummary()`，
   改为受控组件，settings/战绩全部来自 `ControllerSnapshot`，写入走
   `controller.updateSettings(patch)`（与设置面板同一条路径）。
3. **数值规范化收敛**到 `src/ui/format.ts`（`clampStartingStack` / `clampSmallBlind` /
   `clampBigBlind`），首屏与设置面板共用，避免两处 `Math.max(...)` 漂移。
4. **继承模式下改起始筹码/桌人数 → 重建账本**（抽 `resetTable()`，与
   `setCarryOverStacks` 共用）。原因：继承模式开局筹码来自账本
   `[bankroll, ...roster.map(r => r.stack)]`，不读 `settings.startingStack`，
   只 merge 设置会出现「改成 2000，牌桌还是 1000」。
5. **非继承模式下改起始筹码 → 资金按差额平移**，保住「资金 = 起始 + Σ净盈亏」，
   否则顶部显示旧值而牌桌座位是新值，同一屏两个数对不上。

**风险与取舍**

- 「没有战绩」的判据必须从「存档是否存在」改成 `stats.handsPlayed > 0`：
  首屏改参数就会写存档，用 `hasSave` 会把「没有战绩」误报成「已读自存档」。
- 继承模式下改建桌参数会**清零本局战绩**（换桌子语义）。已在首屏与设置面板
  两处写明后果，不做静默处理。
- 未给 `Settings` 加字段（`src/core/types.ts` 冻结），继承模式开关仍走
  `PersistedState.carryOverStacks`。

**验证**

- `tests/e2e/lobby-setup.spec.ts`（4 条）：改参数进桌生效 / 刷新后仍在 /
  非法输入被夹住 / 首屏继承开关可用。
- `tests/e2e/app.spec.ts` 三处旧断言（`.lobby-facts .fact` 只读文本）改为断言控件
  `value`——比旧的 `toContainText` 更强。
- `tests/unit/format.test.ts` 扩到 10 条、`tests/unit/carry-over.test.ts` 扩到 30 条
  （含「继承模式改建桌参数会重建账本」「非继承模式资金平移」）。
- `npm run verify` 11 道闸门全绿：G1｜G2–G7,G10（20 文件 / 297 用例）｜G9a｜G9b｜G9c｜
  G11｜G8（60 passed / 4 skipped，共 64 个用例）。
